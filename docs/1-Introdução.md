
# 1. Introdução

A seção de Introdução apresenta uma visão geral do documento de requisitos e define o escopo do sistema a ser desenvolvido. Ela tem como objetivo descrever a finalidade do sistema, identificar seu público-alvo e fornecer contexto sobre as siglas e termos utilizados ao longo do documento. Além disso, esta seção também contém referências a outros documentos relevantes que suportam o desenvolvimento do sistema.

*(Nota: Este manual foi escrito com base no Guia IEEE para SRS).*

## 1.1 Objetivo do Documento

Descreva o propósito do documento de requisitos, incluindo para quem ele se destina (equipe de desenvolvimento, stakeholders, etc.).

*Exemplo:* Este documento de requisitos foi criado para definir e detalhar as funcionalidades e restrições do sistema, servindo como uma referência central para o desenvolvimento. Destina-se à equipe de desenvolvimento, stakeholders e equipe de testes, fornecendo uma visão clara das expectativas e necessidades do projeto.

## 1.2 Escopo do Software

O objetivo desta seção é descrever de forma geral o que o sistema deverá realizar, destacando os principais objetivos e funcionalidades. Este texto serve como uma introdução ao "minimundo" do sistema, ou seja, uma visão simplificada e resumida do contexto e das necessidades que o sistema irá atender. 

Elementos a incluir:
1. **Visão Geral do Sistema:** Breve explicação do propósito do sistema e das necessidades que ele busca atender (ex: "Qual problema o sistema resolve?").
2. **Principais Objetivos:** Resumo dos objetivos (ex: "automatizar processos", "melhorar a eficiência").
3. **Funcionalidades de Alto Nível:** Enumeração dos recursos principais sem detalhar requisitos específicos (ex: "O sistema permitirá o cadastro de usuários, gerenciamento de produtos e geração de relatórios.").
4. **Limites do Escopo:** Identifique o que está fora do escopo, caso existam limitações claras.
